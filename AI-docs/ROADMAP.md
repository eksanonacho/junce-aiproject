---

## 总原则

1. **先拿到资料再开工**。核心诊断规则（九维/四维、风险标准、场景库）缺失时，只做框架和占位，不编造规则。
2. **先后端核心链路，再做前端页面**。后端规则引擎和报告生成稳定了，前端才有得对接。
3. **先让核心流程跑通（问卷→分析→报告→复核），再做体验优化（PDF美化、品牌、统计看板）。**
4. **一次只做 1-2 个模块**，做完验证通过，再下一个。
5. **涉及客户未提供资料的模块，先搭框架、留 TODO，不自己编规则。**
6. **每模块遵循固定开发流程**：先 plan → 确认 → 写代码 → build 通过 → 测试验证 → 更新文档。

## 阶段 1：项目地基

### 1.1 项目骨架搭建
- 目标：初始化项目仓库、搭建前后端骨架、配置开发环境
- 内容：
  - Git 仓库初始化
  - 前端项目骨架（H5 响应式）
  - 后端项目骨架（NestJS 或其他）
  - 数据库创建（与小程序共用 PostgreSQL 实例、独立数据库）
  - Docker 开发环境配置
  - CI/CD 基础配置
- 涉及数据库：无业务表（仅环境搭建）
- 状态：⬜ 未开始
- 依赖：阶段 0.3 技术方案确认

### 1.2 数据库设计
- 目标：设计并创建 AI 初诊核心数据表
- 预计表：
  - `diagnosis_questionnaires`（问卷模板）
  - `diagnosis_submissions`（客户提交记录）
  - `diagnosis_reports`（初诊报告）
  - `diagnosis_rules`（诊断规则配置）
  - `risk_scenarios`（风险场景库）
  - `service_recommendations`（服务推荐映射）
  - `faq_entries`（FAQ 库）
  - `review_records`（人工复核记录）
- 状态：⬜ 未开始
- 依赖：阶段 0.1 资料到齐（决定表字段）

## 阶段 2：核心业务链路

### 2.1 问卷模块
- 目标：客户填写初诊问卷 → 提交 → 系统保存
- 涉及页面：问卷填写页（手机端优化）、提交成功页
- 涉及接口：POST /questionnaire（提交）、GET /questionnaire（获取问卷题目）
- 涉及表：diagnosis_questionnaires、diagnosis_submissions
- 状态：⬜ 未开始
- 依赖：阶段 0.1 问卷字段确认、阶段 1.1 骨架搭建

### 2.2 规则引擎
- 目标：根据客户填写的问卷答案，按九维/四维规则逐项匹配，输出风险判断
- 核心逻辑：
  - 逐维逐项匹配客户答案
  - 每个检查项判断：正常/轻微风险/中风险/高风险
  - 总体风险等级计算（关键项一票否决 + 取最高风险）
  - 标记是否需要人工复核
- 涉及表：diagnosis_rules、risk_scenarios
- 状态：⬜ 未开始
- 依赖：阶段 0.1 九维/四维规则 + 风险标准 + 场景库确认、阶段 2.1 问卷完成

### 2.3 报告生成模块
- 目标：基于规则引擎输出，生成结构化的初诊报告
- 报告结构（待纪姐确认）：
  - 企业基础画像
  - 总体风险等级
  - 各维度检查结果
  - 发现的问题清单
  - 整改建议
  - 推荐服务
  - 人工复核提醒
  - 免责声明
- 涉及页面：报告展示页（手机+PC）、PDF 导出
- 涉及接口：POST /reports/generate、GET /reports/:id、GET /reports/:id/pdf
- 涉及表：diagnosis_reports
- 状态：⬜ 未开始
- 依赖：阶段 2.2 规则引擎完成、阶段 0.1 报告模板确认

### 2.4 服务推荐模块
- 目标：根据诊断结果，按映射规则推荐君册服务
- 涉及接口：GET /reports/:id/recommendations
- 涉及表：service_recommendations
- 状态：⬜ 未开始
- 依赖：阶段 2.2 规则引擎、阶段 0.1 服务推荐映射规则

## 阶段 3：内部管理

### 3.1 人工复核模块
- 目标：内部员工查看报告、复核、修改（留痕）、审核通过/不通过
- 涉及页面：后台报告列表、报告详情/复核页
- 涉及接口：GET /admin/reports、PATCH /admin/reports/:id/review、PATCH /admin/reports/:id/approve
- 涉及表：review_records
- 权限：会计/主管/管理员
- 状态：⬜ 未开始
- 依赖：阶段 2.3 报告模块完成

### 3.2 后台管理基础
- 目标：查看提交记录、查看报告、导出 PDF
- 涉及页面：后台首页、提交记录列表、报告查看
- 状态：⬜ 未开始
- 依赖：阶段 2.3 报告模块完成

### 3.3 客户留资与商务跟进
- 目标：客户填写手机号后查看报告、记录留资信息、商务跟进
- 涉及接口：POST /leads、GET /admin/leads
- 状态：⬜ 未开始
- 依赖：阶段 2.3 报告模块完成

### 关键判断

- **必须先等资料**：阶段 0.1 不完成，阶段 2 的核心诊断逻辑无法开工。
- **问卷和规则引擎是最核心的两个模块**：它们决定了 AI 初诊的诊断质量和产品价值。
- **报告模块依赖规则引擎**：规则引擎输出什么，报告就展示什么。
- **人工复核是合规底线**：高风险报告必须人工审核后才能给客户。
- **部署可复用小程序基础设施**：Docker、Nginx、PostgreSQL 实例均已就绪。
